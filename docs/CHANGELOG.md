## [0.4.0] - 2026-10-08

### 新增
- **提示词 / 模板 / 检查清单（第四类进化对象）在面板上「可看可管」**：进化页新增「📝 提示词 / 模板 / 检查清单」区 ——
  类型筛选（全部 / 提示词 / 模板 / 检查清单，计数与列出的条目**同源现数**）、新建、编辑（编辑态名称只读：改名 = 新建 + 删旧，
  绝不做静默重命名）、**历史版本**（逐版列出时间与字节数）、删除、只读查看；下方「🧪 待固化候选」
  （`GET /api/prompts/candidates`）只发现「值得固化的模式 + 证据」，点「据此新建」**只把名称与建议类型填进表单**
  （不生成正文、不写任何文件）。可写路径只有两条：`POST /api/prompts/save` 与下面新增的 `DELETE`。
  （此前这四类对象只有后端接口、**前端零入口**，用户点不到 —— 本轮把入口补上。）
- **`DELETE /api/prompts?name=`**：删除**只移除当前版本** `<名>.md`，`.history/<名>/` **原样保留**（历史只增不删，
  与 `save` 的「旧内容逐字节留档」承诺一致）；因此删掉再建同名时**版本号从旧历史接着涨**（不回到 1），
  响应回 `historyKept` 说明保留了几版。越界名（路径分隔符 / 盘符 / `..` / 控制字符 / 超长）一律 **400 且零写入**。
- `/` 首页的接口清单补上此前漏列的 `GET /api/prompts/history` 与 `POST /api/prompts/save`。

### 修复
- **面板打开后聊天区持续左右抖动（真实机器定位，非推断）**：根因是「左移目标」迟滞（hysteresis）的
  **启用条件多写了一条 `sticky.contains(sc)`** —— 而 `sc`（"面积最大的可滚动元素"）本身会在两个面积接近的
  候选之间跳（聊天的滚动区 ↔ 右侧面板的滚动区），`contains(sc)` 于是时真时假 → 迟滞被绕过 → 每次调用都重挑目标，
  在**两个互不包含的兄弟容器**之间来回写 `padding-right`。真机诊断实测：9 次调用里**目标集合切换 8 次**、
  `写入=8 / 快速跳过=0`（幂等快速路径一次都没命中）、速率 2.5 次/秒、由结构观察器（MO）驱动，
  padding 在「聊天主区容器」（**正确**）与「面板底下那根右栏容器」（**错误**）之间反复落
  → 聊天区肉眼可见左右跳。
  **修法：迟滞改为「记忆里的目标只要还活着就锁定，不再重挑」**（与本次挑出的 `sc` 无关；仅当目标脱离文档、
  变成面板自身/包含面板、或面板关闭还原时才重新挑选）。真机复测：目标集合切换 **8 → 1**、
  写入 **8 → 1**、快速跳过 **0 → 6**、速率 **2.5 → 1.0/秒**，抖动消失、目标恒为聊天主区。
  同时收掉另外两处不稳定来源：① `findHeader()` 会把**聊天区内部的"宽而矮"元素**（长消息 / 代码块 / 表格行）
  误判成顶部工具条，导致目标爬升提前 `break`（新增 `sc.contains(el)` 排除聊天区内部内容）；
  ② 找不到聊天滚动区时的**多目标兜底**改为**单目标**（面积最大的那个兄弟），并同样写进迟滞记忆，
  使迟滞与 ±2px 死区在该路径上同样生效；另加"首挑优先排除整个躺在面板底下的目标"。
- **上述「目标锁定」的后续修正（同一轮，第 2 版）：锁定不能锁到「面板底下那根栏」**。第 1 版把迟滞改成
  "锁定"之后，**重启应用**暴露了新问题：冷启动那一次首挑若挑到**面板底下那根右栏**（它同样可滚动、
  面积与聊天滚动区接近，而应用刚启动时聊天区可能还没排完版 → 按"面积最大"它会赢），锁定就把这个错目标
  固定下来 → **面板盖住聊天**（实测；属第 1 版引入的回归）。两处修正：
  ① `chatScrollHost()` **从源头排除整个落在面板那一列**的候选（左边缘 ≥ 面板左边缘）；筛完还有候选才用
     筛后结果，全在面板底下时退回不筛（宁可加错也不能不加）；
  ② **锁定可被打破**：仅当锁定目标整个躺在面板底下、**且确实存在一个不在面板底下的更新候选**时才解锁
     重挑（否则会在"重挑 → 还是它"之间空转、每次写一次 padding = 退化成抖动）；找不到聊天滚动区的
     多目标兜底也改为按「不在面板底下优先、同类再比面积」挑**单一**目标。
  真机复测：重启后**既不抖、聊天也被正确让到左边**。

### 变更
- **浅色主题文字对比度全面达标 + 阴影跟随主题**（用户反馈：浅色下阴影太重、部分文字太淡看不见）：
  - **面板阴影换成「只在左边缘」的一条纯横向渐变**（`.dsh-obs-panel::before` + `--ob-edge-w / -near / -far`），
    **不再用 box-shadow**：① box-shadow 会往**上沿**溢出（面板上沿在工具条下方）→ 观感像「光从右上角往下打」、
    顶部挂着一道影；② 它四周暗度均匀，近边缘那一圈会显出一道硬边。新做法：**顶部/底部一点不出**、
    **无任何竖向方向性**、**近边缘一档 + 外围更淡一档**（α 0.086 → 0.024）、
    **深浅两主题力度与宽度完全一致**（28px，只有色相跟主题走：深色黑 / 浅色蓝灰）。
    弹出层 / 内容查看器 / 提示条仍用令牌化的 box-shadow（`--ob-shadow-pop / -view / -bar`），深浅各一套。
  - **新增一层语义色令牌**（`--ob-info / info2 / ok / ok2 / ok3 / run / bad / bad2 / purple / dim / hi /
    step-on / on-dark / on-dark-dim`，深浅主题各一套），并把样式表里 `color:#HEX` 的硬编码**全部**换成
    `color:var(--ob-X,#HEX)`（**带原值兜底**，因此宿主体外的底栏卡片行为完全不变）。此前这些是
    "深色专用"的浅色调（`#8fb8ff` / `#6ee7b7` / `#fca5a5` / `#93c5fd` …），**在浅色下就是浅字压浅底**。
  - 三级文字 `--ob-tx3`（面板里用得最广的次级文字）：浅色 **2.91:1 → 5.22:1**、深色 **3.16:1 → 5.00:1**；
    浅色下不合格的硬编码文字色 **46 条 → 0 条**；活动步进芯片的白字 **3.51:1 → 6.29/7.90:1**。
  - 新增 `tests/theme-contrast-harness/`：把"太淡"变成**可判定的 WCAG AA 4.5:1** 断言（令牌层 + 规则层 +
    自带永久深底的浮层 + 阴影），共 13 条 —— 修前 46 条不合格、修后 0 条。

## [0.3.0] - 2026-10-06

本版本把项目从「DSH 侧边面板」推进为一个**双向知识闭环**：DSH 与 Obsidian 互为第二大脑。

### 新增
- **DSH 原生面板**（非 iframe 嵌入）：5 个页签 —— 笔记 / 编辑 / 结构 / 进化 / 投喂
- **Obsidian 风格阅读视图**：属性区块、表格、代码块（带语言角标）、双链、标签胶囊、图片，**支持 iframe 视频播放**
- **投喂入库**：拖入 PDF / PPT / 图片 / Office → 识别（自动提取正文、猜标题与标签）→ 可编辑表单 → 加入知识库；图片走多模态队列
- **笔记列表**：删除键（移入回收站，可恢复）+「交给 DSH」交接键（推入 `.dsh/inbox/`）
- **编辑页「新建笔记」**：完整表单态（标题 / 描述 / 标签 / 日期自动填入 / 目标目录 / 正文）
- **结构页目录移动**：整目录搬移，可同时改名
- **回收站**：查看 / 还原 / 删除 / 清空（删除与清空二次确认）；**还原回原目录**（删除时记录原相对路径）
- **进化任务队列**：任务完成后归档到知识库可见目录（可配置 `evolution_log_folder`）
- **会话 → 知识库**：会话右键「导出到 Obsidian」（纪要档：抽掉思考与工具细节）；**自动导出**（存活 ≥2 天且未导出过的会话）+ 候选预览接口
- **开工检索** `GET /api/recall`：一次返回相关笔记 / 可复用技能卡 / 同类历史归档 / 已记录缺口 / 库内习惯（标签、目录、frontmatter 约定）
- **技能提炼「候选发现」** `GET /api/skills/candidates`：只找出**值得沉淀成技能的主题 + 证据**（高频标签 / 高频目录 / 进化归档 / 高分记账），**不生成技能内容**（提炼由 DSH 做）；标签视为主题信号、目录视为容器信号，已有技能卡**降权 ×0.4**（信号仍是"该不该更新/拆分"）；纯只读
- **缺口生命周期**：条目支持 `- [ ]`（未解决）/ `- [x]`（已解决），无勾选框的旧条目视为未解决；`/api/recall` 与 `/api/evolution` **默认只返回未解决**并给出 `openGaps`/`resolvedGaps`，`?includeResolved=1` 看全量；新增 `POST /api/evolution/gaps/resolve`（**只改勾选框 + 行尾追加说明，绝不改写原条目文字**；越界路径一律 400）
- **四条智力指标** `POST/GET /api/metrics`：首轮追问次数↓ · 同类任务耗时↓ · 技能复用↑ · 引用库内来源比例↑，并给出**最近 N 条 vs 更早 N 条的trend对比**；**缺省=未上报（null），绝不代填 0**，另给 `followupsSamples`/`completeTasks` 暴露上报率
- **使用记账与度量（借鉴 Hermes 的「生成候选 → 度量 → 保留更好的」）**：.dsh/stats.jsonl 追加式事件账本 + POST/GET /api/score；/api/recall 每条带 used/success/rework/fail/record 与度量分（metricScore），**并参与排序**（相关性分与度量分分开返回）。置信度用拉普拉斯平滑：1 次成功仅 +16.7，样本 <2 不给 positive/negative 标签
- **侧栏底栏**：`Obsidian` 标准开关（蓝/灰渐入动画）+ 收件箱计数 + 自动导出开关
- **开机自启**：任务计划程序 + 隐藏启动器

### 变更
- 面板从窗口顶端改为**从宿主工具条下方开始**，不再遮挡顶部按钮
- 「聊天区左移」目标改为**最外层且不含工具条的祖先**（此前缩应用根会导致工具条按钮溢出）
- 面板内配色统一为**靛蓝体系**；仅收件箱/回收站**计数徽标**保留琥珀高亮

### 修复
- 笔记列表停在「载入中…」（索引已缓存时提前返回却不渲染）
- 插件热重载**遗留旧面板叠加**（用户看到的永远是最旧那层）
- 切换页面后**左移失效**（会话视图 DOM 被重建，新增结构观察器自愈）
- **聊天不自动置底 / 置底也到不了底**（左移改为幂等零写入，消除每次重算的中间态重排）
- 打开设置等模态弹窗时**面板遮挡**（检测到模态时面板降层）
- 标签提取把 CSS 色值（`#2d2415`）当成标签
- 去掉状态行冗余的「主题：深色」显示
- **检索「整串连续子串」导致多词查询静默漏检**（如 `Hermes 自我进化` 库里有却返回 0）→ 改为**多词 AND 优先 + OR 兜底 + 打分排序**，笔记 / 技能 / 归档 / 缺口**四段统一**
- **技能候选的「已有技能卡」匹配只有单向** → 真实场景（候选名包含技能名 / 全角括号与连字符不同形）漏配，新建的技能卡不被识别 → 改为**双向包含 + 标点宽度归一**，并加防误配边界（短泛名 / <3 字不做包含）
- **收件箱计数不区分「待执行/已完成」** → 处理完徽标也不降，用户以为没人管 → 计数只算未处理（已完成文件保留作记录，另给 `total`/`all`）
- 指标读回时 `Number(null)===0` 会把「未上报耗时」变成 0ms 样本、拉低平均 → 改 `numOrNull()`
- **技能数口径不一致**：面板显示「技能 0」，而库里实际有 10 个 `**/skills/*/SKILL.md` → 统一为「本地 + 库内」同源统计，并区分来源（**库内技能只读，面板不得删除用户文件**）
- **检索 skills 段在灌噪音**：无命中时回退返回「全部技能」，导致每次开工都塞进不相关内容且看似相关 → 改为**只返回真正命中的**（无命中返回空数组 + skillsFallback:false）
- **ecord 把「样本不足」与「无记录」混为一谈** → 拆成

- 技能区标题与列表口径矛盾（计数 10 / 列表 0）→ 标题改为「技能 · 本地 N / 库内 M」，两个来源同源计算
- **含中文的 PowerShell 脚本缺 UTF-8 BOM** → Windows PowerShell 5.1 按 GBK 解析、语法直接失败（**用户会装不上**）；并修掉「删掉写死的默认值后未处理空值分支」导致的报错

### 安全
- 面板 HTML **白名单清洗**（剔除脚本、事件属性、`javascript:` 等危险协议）
- 文件操作（删除 / 移动 / 目录移动 / 回收站）**全部限定在知识库内**，拒绝越界、绝对路径、UNC 与 `..`
- 回收站条目只允许操作 `.dsh/trash/` 内文件；清空不影响其它目录
